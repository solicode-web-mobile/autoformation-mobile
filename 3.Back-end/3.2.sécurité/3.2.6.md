# 📘 3.2.6 — Créer des Gates pour contrôler les actions sur les articles

> Tutoriel 3.2.6 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans les tutoriels précédents, tu as :

* protégé l’espace `/admin` avec le middleware `auth` (3.2.3),
* distingué **Admin / Auteur** avec le champ `is_admin` (3.2.4),
* affiché clairement le profil connecté dans l’interface (3.2.5).

Maintenant, tu vas commencer à **traduire tes règles métier en code Laravel** :

> Qui a le droit **de créer** un article ?
> Qui a le droit **de supprimer** un article, et dans quels cas ?

Pour ça, tu vas utiliser les **Gates** de Laravel.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* définir des **Gates Laravel** dans `AuthServiceProvider` ;
* écrire des règles métier simples avec `Gate::define()` ;
* utiliser les Gates dans un contrôleur pour **autoriser** ou **bloquer** une action (`store`, `destroy`) ;
* tester les scénarios avec un **Auteur** et un **Admin**.

---

## 3️⃣ Pré-requis

Tu dois déjà avoir :

* un projet fil rouge Laravel fonctionnel,

* **l’authentification Laravel UI** en place (3.2.2),

* `/admin` protégé par le middleware `auth` (3.2.3),

* le champ `is_admin` sur `users` et les deux profils :

  * Auteur (`is_admin = 0`),
  * Admin (`is_admin = 1`) (3.2.4),

* un **CRUD d’articles** (au minimum `store` et `destroy`) déjà réalisé dans les versions précédentes.

On suppose que tu as un modèle `Article` et un contrôleur d’articles (par exemple `ArticleController`).

---

## 4️⃣ Rappel métier : quelles règles appliquer ?

Dans la description de l’autoformation V6, les règles sont :

* **Auteur** :

  * ✅ peut **ajouter** des articles,
  * ✅ peut **supprimer uniquement ses propres articles**,
  * ❌ ne peut pas supprimer les articles des autres.

* **Admin** :

  * ❌ ne peut **pas ajouter** d’article,
  * ✅ peut **supprimer n’importe quel article**.

Tu vas créer des Gates pour :

* `create-article` → vérifier si l’utilisateur a le droit de **créer** un article ;
* `delete-article` → vérifier s’il a le droit de **supprimer** un article donné.

---

## 5️⃣ Étapes guidées (N1 — Imiter)

---

### 🧩 Étape 1 — Préparer `AuthServiceProvider` pour les Gates

Les Gates se définissent dans **`app/Providers/AuthServiceProvider.php`**.

**Action**

1. Ouvre le fichier :

   ```text
   app/Providers/AuthServiceProvider.php
   ```

2. En haut du fichier, vérifie que tu as bien l’import de la façade `Gate` :

   ```php
   use Illuminate\Support\Facades\Gate;
   ```

3. Assure-toi aussi que ton modèle `Article` est importé si tu en auras besoin :

   ```php
   use App\Models\Article;
   ```

#### ▶ Résultat attendu

* `AuthServiceProvider` contient bien les `use` nécessaires pour `Gate` et `Article`.

#### 💡 Explication

Les Gates sont définies dans la méthode `boot()` de ce provider.
Tu prépares simplement le fichier pour pouvoir y utiliser `Gate::define()`.

---

### 🧩 Étape 2 — Créer la Gate `create-article`

Cette Gate répond à la question :

> “L’utilisateur connecté a-t-il le droit de **créer un article** ?”

Rappel métier :

* **Auteur** → a le droit de créer,
* **Admin** → n’a pas le droit de créer.

**Action**

1. Dans `AuthServiceProvider`, repère la méthode `boot()` :

   ```php
   public function boot(): void
   {
       $this->registerPolicies();

       //
   }
   ```

2. À l’intérieur de `boot()`, ajoute la définition de la Gate `create-article` :

   ```php
   public function boot(): void
   {
       $this->registerPolicies();

       Gate::define('create-article', function ($user) {
           // Auteur = is_admin = false → peut créer
           // Admin  = is_admin = true  → ne peut pas créer
           return $user->is_admin === false;
       });
   }
   ```

3. Sauvegarde le fichier.

#### ▶ Résultat attendu

* La Gate `create-article` est définie dans `AuthServiceProvider`.

#### 💡 Explication

* La fonction anonyme reçoit l’**utilisateur connecté** (`$user`).
* On renvoie `true` si l’utilisateur est **Auteur**, `false` s’il est Admin.
* Plus tard, tu utiliseras `Gate::allows('create-article')` pour laisser passer ou non.

---

### 🧩 Étape 3 — Créer la Gate `delete-article` (avec paramètre)

Cette Gate répond à la question :

> “L’utilisateur connecté a-t-il le droit de **supprimer cet article précis** ?”

Rappel métier :

* **Auteur** → peut supprimer **ses propres articles uniquement** ;
* **Admin** → peut supprimer **n’importe quel article**.

Tu dois donc comparer :

* le rôle (`is_admin`),
* et, si Auteur, le **propriétaire** de l’article (`user_id` par exemple).

**Action**

1. Toujours dans `boot()`, juste après la Gate précédente, ajoute :

   ```php
   Gate::define('delete-article', function ($user, Article $article) {
       // Admin → peut tout supprimer
       if ($user->is_admin) {
           return true;
       }

       // Auteur → peut supprimer seulement ses propres articles
       return $article->user_id === $user->id;
   });
   ```

2. Sauvegarde le fichier.

#### ▶ Résultat attendu

* `AuthServiceProvider` contient maintenant **deux Gates** :

  * `create-article`,
  * `delete-article`.

#### 💡 Explication

* Cette Gate reçoit **deux arguments** :

  * `$user` → utilisateur connecté,
  * `$article` → article qu’on veut supprimer.

* Cas Admin (`is_admin = true`) → autorisation immédiate (`return true`).

* Cas Auteur → autorisé seulement si l’article appartient à cet utilisateur.

---

### 🧩 Étape 4 — Utiliser les Gates dans le contrôleur d’articles (création)

Tu vas maintenant **utiliser la Gate `create-article`** dans l’action qui crée un article (souvent `store()`).

**Action**

1. Ouvre le contrôleur de tes articles, par exemple :

   ```text
   app/Http/Controllers/ArticleController.php
   ```

2. En haut du fichier, importe la façade `Gate` si ce n’est pas déjà fait :

   ```php
   use Illuminate\Support\Facades\Gate;
   ```

3. Dans la méthode `store()`, ajoute une vérification au début :

   ```php
   public function store(Request $request)
   {
       if (! Gate::allows('create-article')) {
           abort(403);
       }

       // ... validation et création de l’article ...
   }
   ```

4. Sauvegarde le fichier.

#### ▶ Résultat attendu

* Avant de créer un article, le contrôleur vérifie la Gate `create-article`.
* Si la Gate renvoie `false`, l’utilisateur obtient une **erreur 403 (Forbidden)**.

#### 💡 Explication

* `Gate::allows('create-article')` → **true** si l’utilisateur a le droit de créer.
* `abort(403)` → renvoie une page “403 Forbidden” (non autorisé).

Tu viens de rendre le **code contrôleur** cohérent avec tes règles métier.

---

### 🧩 Étape 5 — Utiliser les Gates dans le contrôleur d’articles (suppression)

Tu vas faire la même chose pour la suppression, avec la Gate `delete-article`.

**Action**

1. Dans le même contrôleur, repère la méthode `destroy()` (ou équivalent), par exemple :

   ```php
   public function destroy(Article $article)
   {
       // ...
   }
   ```

2. Au début de cette méthode, ajoute :

   ```php
   public function destroy(Article $article)
   {
       if (! Gate::allows('delete-article', $article)) {
           abort(403);
       }

       // Suppression autorisée :
       $article->delete();

       return redirect()->back()->with('status', 'Article supprimé avec succès.');
   }
   ```

3. Sauvegarde le fichier.

#### ▶ Résultat attendu

* Avant de supprimer un article, le contrôleur vérifie `delete-article` sur **cet article précis**.
* Si la Gate refuse, l’utilisateur obtient un 403 Forbidden.

#### 💡 Explication

* `Gate::allows('delete-article', $article)` passe l’article en **second paramètre** (comme défini dans `AuthServiceProvider`).
* L’Admin passera toujours, l’Auteur seulement si l’article lui appartient.

---

### 🧩 Étape 6 — Tester les scénarios avec Auteur et Admin

Tu vas maintenant vérifier les cas suivants :

* Auteur :

  * ✅ peut créer un article,
  * ✅ peut supprimer **ses propres** articles,
  * ❌ ne peut pas supprimer les articles des autres.

* Admin :

  * ❌ ne peut pas créer d’article,
  * ✅ peut supprimer n’importe quel article.

**Action**

1. Lance le serveur :

   ```bash
   php artisan serve
   ```

2. **Scénario Auteur**

   * Connecte-toi avec ton compte **Auteur** (`is_admin = 0`).
   * Essaie de créer un article → ça doit fonctionner.
   * Crée un article A avec cet Auteur.
   * Connecte-toi avec un autre compte (ou crée un autre utilisateur) et crée un article B.
   * Reviens avec l’Auteur initial :

     * Essaie de supprimer **article A** → doit fonctionner.
     * Essaie de supprimer **article B** → doit donner **403 Forbidden**.

3. **Scénario Admin**

   * Connecte-toi avec ton compte **Admin** (`is_admin = 1`).

   * Essaie d’accéder à la création d’article (formulaire + envoi) :

     * Tu devrais te heurter à un **403** (Gate `create-article`).

   * Essaie de supprimer **article A** et **article B** :

     * la suppression doit fonctionner pour les deux.

#### ▶ Résultat attendu

* Les comportements observés correspondent **exactement** aux règles métier définies.
* Les erreurs 403 apparaissent dans les cas interdits.

---

## 6️⃣ Vérification & erreurs fréquentes

| Problème                                                   | Cause probable                                          | Piste de solution                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Erreur “Class 'Gate' not found”                            | `use Illuminate\Support\Facades\Gate;` manquant         | Ajoute l’import en haut du fichier concerné.                                 |
| Erreur “Target class Article does not exist” dans la Gate  | Modèle `Article` non importé dans `AuthServiceProvider` | Ajoute `use App\Models\Article;` en haut du provider.                        |
| `abort(403)` appelé même pour les cas qui devraient passer | Logique inversée ou erreur dans la Gate                 | Relis le code de la Gate, vérifie les conditions et la valeur de `is_admin`. |
| L’Auteur peut supprimer les articles des autres            | Condition sur `user_id` absente ou incorrecte           | Vérifie que tu compares bien `$article->user_id === $user->id`.              |
| L’Admin ne peut supprimer aucun article                    | Test `if ($user->is_admin)` mal placé ou mal écrit      | Vérifie la condition `if ($user->is_admin) return true;`.                    |

## 7️⃣ Lien avec le projet fil rouge

Dans la version V6 du projet fil rouge :

* tu as maintenant des **règles métiers codées** dans les Gates,
* ton blog Laravel commence à se comporter comme un **vrai back-office** :

  * Auteur → crée des articles, gère les siens,
  * Admin → “nettoie” le contenu, supprime ce qui doit disparaître.

Les tutoriels suivants vont :

* réutiliser ces Gates dans les vues Blade avec `@can` / `@cannot` (3.2.7),
* puis introduire une **Policy** dédiée au modèle `Article` (3.2.8).
