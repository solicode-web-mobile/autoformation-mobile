# 📘 3.2.3 — Protéger l’espace d’administration avec le middleware `auth`

> Tutoriel 3.2.3 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans les tutoriels précédents, tu as :

* compris la différence entre **authentification** et **autorisation** (3.2.1),
* **activé Laravel UI** et testé l’inscription / connexion / déconnexion (3.2.2).

Maintenant, tu vas faire une première vraie **utilisation de l’authentification** :

> **Empêcher les utilisateurs non connectés d’accéder à l’espace d’administration `/admin`.**

Tu vas utiliser pour cela un outil clé de Laravel : le **middleware `auth`**.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* expliquer ce qu’est un **middleware** dans Laravel ;
* utiliser le middleware **`auth`** pour **protéger une route** ;
* créer une **page d’administration simple** accessible uniquement aux utilisateurs connectés ;
* vérifier deux scénarios importants :

  1. **Non connecté →** accès à `/admin` **interdit** → redirection vers `/login` ;
  2. **Connecté →** accès à `/admin` **autorisé**.

---

## 3️⃣ Pré-requis

Avant de commencer, assure-toi que :

* le **projet fil rouge Laravel** fonctionne dans ton navigateur ;
* l’authentification via **Laravel UI** fonctionne :

  * tu peux accéder à `/login` et `/register` ;
  * tu peux créer un compte, te connecter, te déconnecter.

Si ce n’est pas le cas, reviens au tutoriel **3.2.2** avant de continuer.

---

## 4️⃣ Rappel : c’est quoi un middleware ?

En simplifiant :

> Un **middleware** est un “gardien” placé **devant une route**.

* Il reçoit la requête **avant** que la route ne soit exécutée.
* Il peut décider de :

  * **laisser passer** la requête (continuer vers le contrôleur),
  * **bloquer** l’accès (erreur 403, redirection, etc.).

Le middleware **`auth`** est un gardien qui répond à la question :

> “Y a-t-il **un utilisateur connecté** ?”

* ✅ Oui → il laisse passer.
* ❌ Non → il **redirige vers `/login`**.

Dans ce tutoriel, tu vas **brancher ce gardien** sur la route `/admin`.

---

## 5️⃣ Étapes guidées (N1 — Imiter)

---

### 🧩 Étape 1 — Vérifier que l’authentification fonctionne encore

**Action**

1. Ouvre un terminal.

2. Place-toi dans le dossier de ton projet Laravel :

   ```bash
   cd chemin/vers/ton/projet-blog
   ```

3. Lance le serveur :

   ```bash
   php artisan serve
   ```

4. Dans ton navigateur, vérifie que tu peux :

   * afficher `/login`,
   * afficher `/register`,
   * créer un compte et te connecter.

#### ▶ Résultat attendu

* Les pages d’authentification s’affichent correctement.
* Tu peux te connecter et te déconnecter sans erreur.

#### 💡 Explication

Avant de protéger `/admin`, tu dois être sûr que **Laravel sait déjà qui est connecté**.
Sinon, le middleware `auth` ne pourra pas fonctionner correctement.

---

### 🧩 Étape 2 — Créer une route `/admin` simple

Si tu as déjà une route `/admin` dans ton projet, tu peux l’adapter.
Sinon, tu vas créer une **route très simple** avec une vue “Admin”.

#### a) Créer la route `/admin`

**Action**

1. Ouvre le fichier `routes/web.php`.
2. Ajoute (ou adapte) cette route :

   ```php
   Route::get('/admin', function () {
       return view('admin.dashboard');
   })->name('admin.dashboard');
   ```

> 💡 Si `/admin` existe déjà avec un contrôleur, garde ton contrôleur mais adapte plus tard la partie `->middleware('auth')`.

#### b) Créer la vue `admin/dashboard.blade.php`

**Action**

1. Dans `resources/views`, crée un dossier `admin` s’il n’existe pas.

2. Dans ce dossier, crée un fichier `dashboard.blade.php` avec un contenu très simple, par exemple :

   ```blade
   {{-- resources/views/admin/dashboard.blade.php --}}
   @extends('layouts.app')

   @section('content')
       <div class="container">
           <h1>Espace d’administration</h1>
           <p>Bienvenue dans l’admin du blog.</p>

           @auth
               <p>Utilisateur connecté : {{ Auth::user()->name }}</p>
           @endauth
       </div>
   @endsection
   ```

3. Sauvegarde le fichier.

#### ▶ Résultat attendu

* Aller sur `/admin` dans le navigateur affiche maintenant cette page.
* Pour l’instant, **même sans être connecté**, tu peux y accéder (ce n’est pas encore sécurisé).

#### 💡 Explication

Tu viens de créer un **point d’entrée pour l’admin**.
Pour le moment, il est **ouvert à tout le monde**, comme une page publique.
Dans l’étape suivante, tu vas lui mettre un **gardien `auth`** devant.

---

### 🧩 Étape 3 — Protéger `/admin` avec le middleware `auth`

Tu vas maintenant dire à Laravel :

> “Pour accéder à `/admin`, il faut être connecté.”

**Action**

1. Retourne dans `routes/web.php`.

2. Modifie la route `/admin` pour y ajouter le middleware `auth` :

   ```php
   Route::get('/admin', function () {
       return view('admin.dashboard');
   })->middleware('auth')->name('admin.dashboard');
   ```

3. Sauvegarde le fichier.

#### ▶ Résultat attendu

* La route `/admin` est maintenant protégée par `->middleware('auth')`.

#### 💡 Explication

La méthode `middleware('auth')` dit à Laravel :

* “Avant de faire tourner cette route, **exécute le middleware `auth`**.”
* Si aucun utilisateur n’est connecté, le middleware `auth` **redirige automatiquement vers `/login`**.

Tu viens donc de transformer `/admin` en **espace réservé aux utilisateurs connectés**.

---

### 🧩 Étape 4 — Tester les scénarios dans le navigateur

Tu vas maintenant vérifier que le comportement est bien celui attendu.

#### 🔍 Scénario 1 — Utilisateur non connecté

**Action**

1. Assure-toi d’être **déconnecté** (clique sur “Logout” / “Se déconnecter” si besoin).
2. Va sur l’URL : `/admin`.

#### ▶ Résultat attendu

* Tu n’accèdes **pas** à la page d’admin.
* Tu es **redirigé vers `/login`**.

> Si tu arrives quand même sur la page d’admin sans être connecté, c’est que le middleware `auth` ne s’exécute pas correctement (vérifie la route).

---

#### 🔍 Scénario 2 — Utilisateur connecté

**Action**

1. Va sur `/login`.
2. Connecte-toi avec un compte que tu as créé (par exemple lors du tutoriel 3.2.2).
3. Une fois connecté, va sur `/admin`.

#### ▶ Résultat attendu

* Cette fois, tu accèdes à la page d’admin.
* Tu vois le message “Bienvenue dans l’admin du blog.”
* Si tu as laissé le code `{{ Auth::user()->name }}`, tu dois voir le **nom de l’utilisateur connecté**.

---

#### 🔍 Scénario 3 — Déconnexion puis retour à `/admin`

**Action**

1. Sur n’importe quelle page, clique sur le bouton / lien de **déconnexion**.
2. Une fois déconnecté, tape de nouveau `/admin` dans la barre d’adresse.

#### ▶ Résultat attendu

* Tu es **à nouveau redirigé vers `/login`** (comme dans le scénario 1).

---

### 🧩 Étape 5 — (Optionnel) Protéger plusieurs routes avec un groupe

> 🔎 Cette partie est optionnelle mais utile pour la suite du projet.

Si tu as plusieurs routes d’admin (par exemple `/admin`, `/admin/articles`, `/admin/users`), au lieu de mettre `->middleware('auth')` sur chaque route, tu peux :

* créer un **groupe de routes** avec middleware `auth`.

**Action**

1. Dans `routes/web.php`, tu peux organiser tes routes d’admin comme ceci :

   ```php
   Route::middleware('auth')->group(function () {
       Route::get('/admin', function () {
           return view('admin.dashboard');
       })->name('admin.dashboard');

       // Exemple : route future pour gérer les articles en admin
       // Route::get('/admin/articles', [ArticleAdminController::class, 'index'])
       //     ->name('admin.articles.index');
   });
   ```

2. Sauvegarde et teste `/admin` comme tout à l’heure.

#### ▶ Résultat attendu

* `/admin` reste **protégé** (non connecté → redirection vers `/login`).
* Toutes les routes dans le groupe hériteront du middleware `auth`.

#### 💡 Explication

Le **groupe de routes** permet de :

* éviter les répétitions de `->middleware('auth')` sur chaque ligne ;
* regrouper toutes les **routes d’administration** au même endroit.

C’est une bonne habitude quand le projet commence à grandir.

## 6️⃣ Vérification & erreurs fréquentes

| Problème                                              | Cause probable                                          | Piste de solution                                                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| En étant non connecté, je vois quand même `/admin`    | Middleware `auth` oublié sur la route                   | Vérifie que tu as bien `->middleware('auth')` sur la route `/admin`.                                                               |
| `/admin` me donne une erreur “view not found”         | Vue `admin/dashboard.blade.php` manquante ou mal nommée | Vérifie le chemin exact : `resources/views/admin/dashboard.blade.php`.                                                             |
| Je suis toujours redirigé vers `/login` même connecté | Problème d’authentification ou de session               | Vérifie que la connexion fonctionne bien (`/login`), et que tu vois `Auth::user()` dans une vue.                                   |
| Erreur sur `Auth::user()`                             | Classe `Auth` non importée dans la vue ou le contrôleur | Dans une vue Blade, `Auth::user()` est disponible sans import ; dans un contrôleur, ajoute `use Illuminate\Support\Facades\Auth;`. |
| Erreur base de données lors de l’inscription          | Migrations non lancées ou base mal configurée           | Vérifie `.env`, puis lance `php artisan migrate`.                                                                                  |

## 7️⃣ Lien avec le projet fil rouge

Ce tutoriel ajoute une **première vraie couche de sécurité** à ton blog Laravel :

* l’espace `/admin` devient un **back-office privé** ;
* seuls les utilisateurs connectés peuvent y accéder.

Dans les tutoriels suivants, tu vas :

* différencier les profils **Admin / Auteur** (`is_admin`) (3.2.4) ;
* **afficher le profil connecté** dans l’interface (3.2.5) ;
* utiliser des **Gates** et une **Policy** pour contrôler les actions sur les articles (3.2.6 → 3.2.8).
