# 📘 3.2.7 — Utiliser les Gates dans les vues Blade avec `@can` / `@cannot`

> Tutoriel 3.2.7 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans le tutoriel **3.2.6**, tu as :

* créé des **Gates** pour traduire tes règles métier :

  * `create-article` → qui peut **créer** un article ?
  * `delete-article` → qui peut **supprimer** un article ?

* utilisé ces Gates dans les **contrôleurs** (`store`, `destroy`) pour bloquer les actions non autorisées.

Problème :

> Dans l’interface, les boutons “Ajouter” / “Supprimer” sont peut-être encore visibles pour tout le monde,
> même quand l’action sera refusée par le contrôleur (403).

Ce n’est pas très agréable pour l’utilisateur…

Dans ce tutoriel, tu vas :

> **réutiliser les Gates dans les vues Blade**, grâce à `@can` et `@cannot`,
> pour **afficher ou cacher les boutons** selon les droits réels.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* utiliser `@can` et `@cannot` dans une vue Blade ;
* connecter ces directives aux Gates définies dans `AuthServiceProvider` ;
* **masquer le bouton “Ajouter un article”** pour l’Admin (il ne peut pas créer) ;
* **masquer le bouton “Supprimer”** quand l’utilisateur n’a pas le droit de supprimer l’article ;
* tester le comportement avec un **Auteur** et un **Admin**.

---

## 3️⃣ Pré-requis

Tu dois avoir déjà :

* l’authentification Laravel UI (3.2.2),
* `/admin` protégé par `auth` (3.2.3),
* les profils **Admin / Auteur** avec `is_admin` (3.2.4),
* le profil visible dans l’interface (3.2.5),
* les Gates définies et utilisées dans les contrôleurs (3.2.6) :

  * `create-article`,
  * `delete-article`.

Tu dois aussi avoir des vues Blade pour :

* la **liste des articles** (avec boutons “Supprimer”),
* l’**interface d’admin** ou un endroit où tu mets le bouton “Ajouter un article”.

---

## 4️⃣ Rappel : Gates créées dans 3.2.6

Dans `app/Providers/AuthServiceProvider.php`, tu dois avoir quelque chose comme :

```php
Gate::define('create-article', function ($user) {
    // Auteur → peut créer, Admin → ne peut pas
    return $user->is_admin === false;
});

Gate::define('delete-article', function ($user, Article $article) {
    // Admin → peut supprimer tout
    if ($user->is_admin) {
        return true;
    }

    // Auteur → peut supprimer seulement ses propres articles
    return $article->user_id === $user->id;
});
```

Tu vas maintenant **réutiliser ces mêmes Gates** côté Blade.

---

## 5️⃣ Les directives Blade `@can` et `@cannot`

* `@can('gate-name')`
  → le bloc est affiché **seulement si** la Gate renvoie `true`.

* `@cannot('gate-name')`
  → l’inverse : le bloc est affiché **seulement si** la Gate renvoie `false`.

Pour une Gate **sans paramètre** (comme `create-article`) :

```blade
@can('create-article')
    {{-- contenu réservé aux utilisateurs autorisés --}}
@endcan
```

Pour une Gate **avec paramètre** (comme `delete-article`, qui reçoit un `Article`) :

```blade
@can('delete-article', $article)
    {{-- contenu affiché seulement si l’utilisateur peut supprimer cet article --}}
@endcan
```

## 6️⃣ Étapes guidées (N1 — Imiter)

---

### 🧩 Étape 1 — Cacher le bouton “Ajouter un article” pour l’Admin

Rappel métier :

* **Auteur** → a le droit de créer un article,
* **Admin** → n’a **pas** le droit de créer.

Tu vas faire en sorte que :

* le **bouton “Ajouter un article”** n’apparaisse **que si** la Gate `create-article` renvoie `true`.

**Action**

1. Ouvre la vue Blade où se trouve le bouton “Ajouter un article”.
   Par exemple : `resources/views/admin/articles/index.blade.php` ou similaire.

2. Repère le code du bouton, par exemple :

   ```blade
   <a href="{{ route('admin.articles.create') }}" class="btn btn-primary">
       Ajouter un article
   </a>
   ```

3. Entoure ce bouton avec la directive `@can('create-article')` :

   ```blade
   @can('create-article')
       <a href="{{ route('admin.articles.create') }}" class="btn btn-primary">
           Ajouter un article
       </a>
   @endcan
   ```

4. Sauvegarde la vue.

#### ▶ Résultat attendu

* Lorsque tu es connecté en **Auteur**, le bouton “Ajouter un article” est visible.
* Lorsque tu es connecté en **Admin**, le bouton **disparaît**.

#### 💡 Explication

* `@can('create-article')` appelle la Gate définie dans `AuthServiceProvider`.
* Si la Gate renvoie `true` (Auteur), le bouton est affiché.
* Si la Gate renvoie `false` (Admin), le bouton est caché.

---

### 🧩 Étape 2 — Cacher le bouton “Supprimer” pour les articles non autorisés

Rappel métier :

* **Auteur** → peut supprimer **ses propres articles**,
* **Admin** → peut supprimer **tous** les articles.

Le bouton “Supprimer” ne doit donc être visible que si :

> la Gate `delete-article` renvoie `true` pour l’article en question.

**Action**

1. Ouvre la vue qui affiche la **liste des articles** dans l’admin.
   Par exemple : `resources/views/admin/articles/index.blade.php`.

2. Repère la boucle qui affiche les articles, quelque chose comme :

   ```blade
   @foreach ($articles as $article)
       <tr>
           <td>{{ $article->title }}</td>
           <td>
               <form action="{{ route('admin.articles.destroy', $article) }}" method="POST">
                   @csrf
                   @method('DELETE')
                   <button type="submit" class="btn btn-danger btn-sm">
                       Supprimer
                   </button>
               </form>
           </td>
       </tr>
   @endforeach
   ```

3. Entoure le formulaire (ou le bouton) avec `@can('delete-article', $article)` :

   ```blade
   @foreach ($articles as $article)
       <tr>
           <td>{{ $article->title }}</td>
           <td>
               @can('delete-article', $article)
                   <form action="{{ route('admin.articles.destroy', $article) }}" method="POST">
                       @csrf
                       @method('DELETE')
                       <button type="submit" class="btn btn-danger btn-sm">
                           Supprimer
                       </button>
                   </form>
               @endcan
           </td>
       </tr>
   @endforeach
   ```

4. Sauvegarde la vue.

#### ▶ Résultat attendu

* Pour un **Auteur** :

  * le bouton “Supprimer” s’affiche **seulement** sur ses propres articles ;
  * il **disparaît** sur les articles écrits par d’autres.
* Pour un **Admin** :

  * le bouton “Supprimer” s’affiche sur **tous** les articles.

#### 💡 Explication

La vue Blade appelle :

```php
Gate::allows('delete-article', $article)
```

en arrière-plan.
C’est exactement la même logique que celle utilisée dans ton contrôleur `destroy()`.

---

### 🧩 Étape 3 — (Optionnel) Afficher un message avec `@cannot`

Tu peux aussi afficher une information lorsqu’un utilisateur **n’a pas** le droit de faire une action.

Par exemple, tu pourrais indiquer à un Auteur qu’il ne peut pas supprimer certains articles.

**Action**

1. Toujours dans la vue de liste des articles, sous le bouton (ou à la place), tu peux ajouter :

   ```blade
   @cannot('delete-article', $article)
       <small class="text-muted">
           Vous ne pouvez pas supprimer cet article.
       </small>
   @endcannot
   ```

2. Place ce bloc au bon endroit (par exemple dans la même colonne, en dessous du bouton ou à la place du bouton si tu veux afficher un texte).

#### ▶ Résultat attendu

* Si l’utilisateur **n’a pas** le droit de supprimer l’article :

  * le bouton “Supprimer” est caché,
  * un petit message “Vous ne pouvez pas supprimer cet article.” peut apparaître (si tu as choisi de l’afficher).

#### 💡 Explication

* `@can` → affichage si **autorisé**.
* `@cannot` → affichage si **non autorisé**.

Cela permet d’être **plus explicite** côté interface.

---

### 🧩 Étape 4 — Tester tous les scénarios

Tu dois maintenant vérifier que l’interface est cohérente avec les règles métier.

**Action**

1. Lance le serveur :

   ```bash
   php artisan serve
   ```

2. **Scénario Auteur**

   * Connecte-toi avec le compte Auteur (`is_admin = 0`).
   * Va sur la page d’admin des articles.
   * Vérifie que :

     * le bouton **“Ajouter un article” est visible** ;
     * pour un article **qu’il a écrit** → le bouton “Supprimer” est visible ;
     * pour un article **écrit par un autre** → le bouton “Supprimer” est caché (et éventuellement un message apparaît).

3. **Scénario Admin**

   * Déconnecte-toi puis reconnecte-toi avec le compte Admin (`is_admin = 1`).
   * Va sur la page d’admin des articles.
   * Vérifie que :

     * le bouton **“Ajouter un article” n’est pas visible** (Admin ne crée pas d’articles) ;
     * le bouton “Supprimer” est visible pour **tous** les articles.

#### ▶ Résultat attendu

* L’interface est **cohérente** :

  * aucun bouton “fantôme” qui affiche une action impossible,
  * les boutons affichés correspondent réellement aux droits de l’utilisateur.

## 7️⃣ Vérification & erreurs fréquentes

| Problème                                                 | Cause probable                                            | Piste de solution                                                                       |
| -------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Erreur “Call to a member function … on null” dans la vue | Utilisation de `Auth::user()` sans vérifier la connexion  | Utilise `@auth` / `@guest` ou laisse `@can` gérer avec auth.                            |
| Bouton “Ajouter” visible aussi pour Admin                | Gate `create-article` mal définie ou non utilisée         | Vérifie la Gate dans `AuthServiceProvider` et le `@can('create-article')`.              |
| Bouton “Supprimer” jamais visible                        | Mauvais paramètre dans `@can('delete-article', $article)` | Vérifie que `$article` est bien passé à la Gate et qu’il a un `user_id`.                |
| L’Auteur voit “Supprimer” sur les articles des autres    | Condition de la Gate `delete-article` incorrecte          | Vérifie que tu compares bien `$article->user_id === $user->id`.                         |
| Rien ne change en modifiant la vue                       | Tu édites la mauvaise vue ou le mauvais layout            | Vérifie le chemin du fichier et la vue réellement utilisée dans les routes/contrôleurs. |

## 8️⃣ Lien avec le projet fil rouge

Grâce à ce tutoriel, ton **back-office** :

* n’affiche les boutons d’action que lorsque l’utilisateur a réellement le droit de les utiliser ;
* évite les surprises du type “je vois un bouton → je clique → 403 Forbidden” ;
* offre une interface plus **claire** et plus **pro** :

  * Auteur → voit ce qu’il peut faire sur **ses** articles,
  * Admin → voit qu’il a des pouvoirs plus larges.

En combinant :

* **middleware `auth`** (protection des routes),
* **Gates dans les contrôleurs** (protection des actions),
* **Gates dans les vues** (interface cohérente),

tu construis une sécurité **complète** pour cette version V6.

Le prochain tutoriel (**3.2.8**) te fera découvrir les **Policies** Laravel, qui permettent de regrouper toute la logique d’autorisation liée au modèle `Article` dans une classe dédiée.
