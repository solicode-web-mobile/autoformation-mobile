# 📘 3.2.2 — Activer Laravel UI sur le projet fil rouge

> Tutoriel 3.2.2 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans le tutoriel **3.2.1**, tu as clarifié la différence entre :

* **authentification** : *qui est connecté ?*
* **autorisation** : *qu’a-t-il le droit de faire ?*

Dans ce tutoriel, tu passes au **concret** : tu vas **activer Laravel UI** sur le projet fil rouge pour obtenir :

* des **vues prêtes à l’emploi** pour s’inscrire et se connecter ;
* des **routes d’authentification** déjà configurées ;
* un **système d’authentification fonctionnel** (inscription, connexion, déconnexion).

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* installer le package **`laravel/ui`** sur un projet existant ;
* générer le **scaffolding d’authentification** (vues + routes) ;
* lancer les commandes nécessaires (migrations, npm…) pour que les écrans de login/register fonctionnent ;
* **tester** l’inscription, la connexion et la déconnexion sur ton projet fil rouge.

---

## 3️⃣ Pré-requis

Avant de commencer, tu dois :

* avoir le **projet fil rouge Laravel** fonctionnel (pages publiques + CRUD d’articles) ;
* savoir :

  * lancer le serveur Laravel :
    `php artisan serve`
  * exécuter les migrations :
    `php artisan migrate`
  * installer des packages avec **Composer**.

> 💡 Si ton projet ne démarre pas, règle d’abord les erreurs avant de continuer ce tutoriel.

---

## 4️⃣ Vue d’ensemble de ce que tu vas faire

Dans ce tutoriel, tu vas suivre **4 grandes étapes** :

1. Vérifier que ton projet est prêt pour recevoir Laravel UI.
2. Installer le package **`laravel/ui`** avec Composer.
3. Générer les fichiers d’authentification (vues + routes).
4. Lancer les commandes front nécessaires et **tester** l’authentification dans le navigateur.

---

## 5️⃣ Étapes guidées (N1 — Imiter)

Pour chaque étape : **Action → Résultat attendu → Explication**.

---

### 🧩 Étape 1 — Ouvrir et lancer le projet fil rouge

**Action**

1. Ouvre ton terminal (ou PowerShell / Git Bash).

2. Place-toi dans le dossier de ton projet fil rouge Laravel, par exemple :

   ```bash
   cd chemin/vers/ton/projet-blog
   ```

3. Vérifie que tu vois bien les dossiers classiques d’un projet Laravel : `app`, `routes`, `resources`, etc.

4. Lance le serveur de développement :

   ```bash
   php artisan serve
   ```

5. Ouvre ton navigateur et va sur l’URL affichée (souvent `http://127.0.0.1:8000`).

#### ▶ Résultat attendu

* Le projet fil rouge s’affiche (page d’accueil du blog).
* Aucun message d’erreur critique.

#### 💡 Explication

Avant d’ajouter Laravel UI, tu dois être sûr que **ton projet actuel fonctionne**.
Sinon, tu ne sauras pas si une erreur vient de Laravel UI ou d’un problème ancien.

---

### 🧩 Étape 2 — Installer le package `laravel/ui` avec Composer

**Action**

1. Arrête le serveur Laravel (touche `Ctrl + C` dans le terminal où il tourne).

2. Dans le même dossier du projet, exécute :

   ```bash
   composer require laravel/ui
   ```

3. Attends la fin de l’installation (pas d’erreur en rouge).

#### ▶ Résultat attendu

* Le package `laravel/ui` est installé dans ton projet.
* Tu vois des lignes indiquant l’installation de `laravel/ui` par Composer.

#### 💡 Explication

Laravel n’installe plus l’authentification complète par défaut.
Le package **`laravel/ui`** sert à **générer les vues, routes et contrôleurs d’authentification** (login, register, mot de passe oublié…) sur un projet existant.

---

### 🧩 Étape 3 — Générer le scaffolding d’authentification

**Action**

> ℹ️ Il existe plusieurs variantes (`--auth`, `--bootstrap`, `--vue`, etc.).
> En N1, tu imites une commande donnée par ton formateur.
> Exemple classique avec Bootstrap + auth :

1. Dans le terminal, tape :

   ```bash
   php artisan ui:auth
   ```

   ou, selon la consigne du formateur :

   ```bash
   php artisan ui:auth
   ```

2. Observe les messages affichés : Laravel te signale les fichiers générés/modifiés.

#### ▶ Résultat attendu

* Les vues d’authentification sont créées dans `resources/views/auth` et `resources/views/layouts`.
* Les routes d’authentification sont ajoutées dans `routes/web.php` (souvent via un appel `Auth::routes();`).

#### 💡 Explication

Cette commande demande à Laravel :

* de **créer les pages nécessaires** pour s’inscrire, se connecter, réinitialiser un mot de passe ;
* d’**ajouter les routes** correspondantes (`/login`, `/register`, `/password/reset`, etc.) ;
* d’installer un **layout de base** pour ces vues (avec Bootstrap si tu as utilisé `bootstrap`).

Tu n’écris pas encore les vues à la main : **tu imites** une commande qui génère tout pour toi.

---

### 🧩 Étape 4 — Lancer les commandes front (npm)

> ⚠️ Étape parfois déjà faite dans ton projet.
> Si ton formateur te dit que ce n’est pas nécessaire (ou si ton projet utilise déjà un front compilé), tu peux adapter.

**Action**

1. Dans le terminal, installe les dépendances front si ce n’est pas déjà fait :

   ```bash
   npm install
   ```

2. Puis compile les assets :

   ```bash
   npm run dev
   ```

   ou

   ```bash
   npm run build
   ```

   selon la consigne ou la version de Laravel.

#### ▶ Résultat attendu

* La compilation se termine **sans erreur critique**.
* Les fichiers CSS/JS nécessaires aux vues d’authentification sont générés.

#### 💡 Explication

Les vues générées par Laravel UI utilisent des **ressources front** (CSS, JS).
Les commandes `npm install` et `npm run dev` permettent d’installer les librairies nécessaires et de **compiler** ces ressources pour que les pages de login/register s’affichent correctement.

---

### 🧩 Étape 5 — Vérifier les routes d’authentification

**Action**

1. Ouvre le fichier `routes/web.php` dans ton éditeur de code.

2. Cherche la ligne (ou similaire) :

   ```php
   Auth::routes();
   ```

3. Facultatif : dans le terminal, tu peux lister les routes liées à l’authentification :

   ```bash
   php artisan route:list
   ```

   et repérer les routes comme `/login`, `/register`, etc.

#### ▶ Résultat attendu

* Le fichier `routes/web.php` contient bien l’appel à `Auth::routes();` ou des routes équivalentes générées par Laravel UI.
* Tu vois (dans `route:list`) des routes de type `login`, `logout`, `register`.

#### 💡 Explication

`Auth::routes();` demande à Laravel d’enregistrer **un ensemble de routes préconfigurées d’authentification** :

* `/login`
* `/logout`
* `/register`
* et d’autres liées au mot de passe.

C’est ce qui va te permettre d’accéder directement aux pages de login/register dans ton navigateur.

---

### 🧩 Étape 6 — Tester l’inscription et la connexion dans le navigateur

**Action**

1. Relance le serveur Laravel :

   ```bash
   php artisan serve
   ```

2. Dans le navigateur, va sur :

   * `/login` → page de connexion ;
   * `/register` → page d’inscription.

3. Sur la page `/register` :

   * crée un **premier compte test** (par exemple un futur Auteur) ;
   * valide le formulaire.

4. Vérifie que :

   * après l’inscription, tu es **connecté** automatiquement ;
   * tu vois un lien ou bouton pour te **déconnecter**.

5. Clique sur le bouton de **déconnexion** (souvent “Logout” ou “Se déconnecter”) et vérifie que la session est bien fermée.

#### ▶ Résultat attendu

* La page `/register` s’affiche correctement.
* Tu peux créer un compte, qui s’enregistre dans la base (table `users`).
* Tu peux te connecter et te déconnecter sans erreur.

#### 💡 Explication

Tu viens de **valider que l’authentification fonctionne** dans ton projet fil rouge :

* inscription d’un nouvel utilisateur → enregistrement en base ;
* connexion → session utilisateur active (Laravel sait qui est connecté via `Auth::user()`).
* déconnexion → session fermée.

C’est la base indispensable avant de sécuriser `/admin` ou de différencier les rôles (Admin / Auteur) dans les prochains tutoriels.

---

## 6️⃣ Vérification & erreurs fréquentes

| Problème                                                 | Cause probable                                       | Piste de solution                                                                      |
| -------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Erreur lors de `composer require laravel/ui`             | Problème de connexion internet ou version PHP        | Vérifie ta connexion, mets à jour Composer / PHP si besoin.                            |
| Les pages `/login` ou `/register` donnent une erreur 404 | `Auth::routes();` manquant dans `web.php`            | Ajoute ou vérifie la ligne `Auth::routes();` dans `routes/web.php`.                    |
| Erreurs lors de `npm install` ou `npm run dev`           | Node/npm pas installés ou version incompatible       | Vérifie l’installation de Node.js et npm, demande au formateur la version recommandée. |
| Après inscription, rien ne s’enregistre                  | Problème de base de données ou migrations non faites | Vérifie `.env`, lance `php artisan migrate`, regarde la table `users`.                 |
| La vue d’auth n’a pas de style (CSS)                     | Assets non compilés                                  | Relance `npm run dev` et recharge la page (Ctrl+F5).                                   |

---

## 7️⃣ Lien avec le projet fil rouge

Dans le projet fil rouge :

* tu vas bientôt **protéger l’admin** du blog (`/admin`) avec le middleware `auth` (tutoriel 3.2.3) ;
* tu vas créer des **profils Admin / Auteur** avec un champ `is_admin` (tutoriels 3.2.4 et 3.2.5) ;
* tu utiliseras **Gates et Policy** pour contrôler finement les actions sur les articles.

Tout cela repose sur **une condition simple** :

> “Laravel doit savoir qui est connecté.”

C’est exactement ce que tu viens de mettre en place avec **Laravel UI**.

---

## 8️⃣ Pistes N2 / N3 (optionnel)

* **N2 — Adapter**

  * Personnaliser les vues de login/register (logo du projet, textes, langue).
  * Modifier la redirection après connexion (par exemple vers `/admin`).

* **N3 — Transposer**

  * Remplacer ce système par un autre (Sanctum, Breeze, Jetstream…) dans un contexte plus “pro”.
  * Relier l’authentification Web à une **API** consumée par une application mobile.
