# 🔐 Sécurité et accès à l’admin (Laravel)

## Pourquoi suivre cette autoformation ?

Dans un blog Laravel, la partie administration permet de gérer les articles et les contenus sensibles.  
Si cette zone n’est pas protégée, n’importe qui peut modifier ou supprimer les données.

Cette autoformation te montre comment :

- limiter l’accès à l’espace admin,
- distinguer les profils **Admin / Auteur**,
- contrôler finement qui a le droit de créer ou supprimer des articles.

Tu poses ici la **base de la sécurité** qui sera ensuite renforcée en N2/N3 (rôles Spatie, permissions avancées).

---

## Objectifs de l’autoformation

À la fin de cette autoformation, tu seras capable de :

- mettre en place une **authentification Laravel UI** et protéger l’accès à l’admin avec le middleware `auth` ;
- créer deux profils simples (**Admin / Auteur**) avec un champ `is_admin` et les afficher clairement dans l’interface ;
- utiliser des **Gates Laravel** pour contrôler qui peut créer ou supprimer un article ;
- mettre en place une **première Policy** sur le modèle `Article` pour centraliser une règle d’autorisation.

---

## À qui s’adresse ce module ?

Cette autoformation est faite pour toi si :

- tu as déjà :
  - les bases de **Laravel** (routes, contrôleurs, modèles, vues Blade),
  - un **CRUD Article** qui fonctionne dans le projet fil rouge ;
- tu veux :
  - éviter qu’un utilisateur non autorisé accède à l’admin,
  - comprendre comment Laravel gère les rôles simples et les autorisations,
  - préparer le terrain pour une sécurité plus “pro” avec Spatie en N2/N3.

## 🎯 Livrables attendus (fin d’autoformation)

À la fin, tu dois être capable de montrer :

- une version du **blog Laravel** où :
  - l’accès à l’admin est protégé par **auth**,
  - les profils **Admin / Auteur** fonctionnent et sont visibles dans l’interface,
  - les actions sur les articles respectent les règles définies (Auteur crée et supprime ses articles, Admin supprime tout) grâce aux **Gates** ;
- une **Policy simple** sur `Article` utilisée dans au moins une action (par exemple la suppression), via `@can` ou `authorize`.

Ces livrables serviront ensuite de base pour les exercices **N2 (Adapter)** et les défis **N3 (Créer / Transposer)** autour des rôles et permissions avancés (Spatie).
