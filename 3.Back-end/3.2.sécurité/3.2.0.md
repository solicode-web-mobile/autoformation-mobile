# 🛡️ V6 — Sécurité et accès à l’admin (N1)

## Pourquoi suivre cette autoformation ?

Dans les versions précédentes du projet fil rouge, tu as déjà :

* mis en place l’interface publique du blog,
* réalisé un **CRUD d’articles** avec Laravel,
* manipulé les routes, contrôleurs, vues Blade et modèles Eloquent.

Cette autoformation V6 te fait passer à une nouvelle étape : la **sécurité du back-office** du blog Laravel.
Tu vas :

* mettre en place une **authentification complète** avec Laravel UI,
* **protéger l’espace d’administration** (`/admin`) avec le middleware `auth`,
* gérer deux profils simples (Admin / Auteur) avec un champ `is_admin`,
* utiliser les **Gates** et une **Policy** pour contrôler les actions sur les articles.

La version V6 répond à la question :

> “Dans l’admin du blog, **qui a le droit de faire quoi**, et comment le coder proprement dans Laravel ?”

Ce que tu feras ici en **N1** sera ensuite :

* **rejoué en live coding** en N2 (même version réalisée en séance guidée),
* **étendu** en N3 vers une sécurité plus “pro” (rôles Spatie, permissions fines, doc “Rôles → Actions”).

---

## Objectifs de l’autoformation

À la fin de cette autoformation, tu seras capable de :

* mettre en place une **authentification Laravel UI** et **protéger** l’espace `/admin` avec le middleware `auth` ;
* distinguer deux profils simples (**Admin / Auteur**) avec un champ `is_admin` et rendre cette différence **visible dans l’interface** ;
* utiliser des **Gates** et une **Policy** pour contrôler les actions sur les articles (ajout, suppression) selon le profil connecté.

---

## À qui s’adresse ce module ?

Cette autoformation est faite pour toi si :

* tu as déjà :

  * travaillé sur le projet fil rouge Laravel,
  * réalisé ou compris un **CRUD d’articles**,
  * manipulé les routes, contrôleurs, vues Blade et modèles Eloquent ;
* tu veux :

  * **sécuriser un back-office Laravel**,
  * comprendre la différence entre **authentification** (se connecter) et **autorisation** (avoir le droit d’agir),
  * préparer la suite : utilisation de **Spatie Laravel Permission** et sécurité avancée en N2 / N3.

## 📘 Unités d’apprentissage (UAs) couvertes

> Les tutoriels sont numérotés **3.2.1 → 3.2.8** dans l’ordre conseillé de l’autoformation.

### UA 3.2.U1 — Authentification avec Laravel UI

Objectif : mettre en place une authentification standard et distinguer routes publiques / routes protégées.

* **Tutoriel 3.2.1 — Découvrir l’authentification et l’autorisation dans Laravel**
  Comprendre, sur des exemples concrets, la différence entre *authentification* (qui est connecté ?) et *autorisation* (qu’a-t-il le droit de faire ?) appliquée au blog du projet fil rouge.

* **Tutoriel 3.2.2 — Activer Laravel UI sur le projet fil rouge**
  Installer `laravel/ui`, générer les vues d’authentification, configurer les routes et tester l’inscription, la connexion et la déconnexion.

* **Tutoriel 3.2.3 — Protéger l’espace d’administration avec le middleware `auth`**
  Protéger la route `/admin` avec le middleware `auth` et vérifier les scénarios : non connecté → redirection vers `/login`, connecté → accès autorisé.

---

### UA 3.2.U2 — Gestion basique des profils utilisateurs

Objectif : créer et distinguer deux profils utilisateurs simples (Admin / Auteur) et rendre la différence visible.

* **Tutoriel 3.2.4 — Gérer les profils Admin / Auteur avec `is_admin`**
  Ajouter un champ booléen `is_admin` à la table `users`, créer un compte Admin et un compte Auteur, et adapter le modèle `User`.

* **Tutoriel 3.2.5 — Afficher le profil connecté dans l’interface**
  Utiliser l’utilisateur connecté (`Auth::user()`) et le champ `is_admin` pour afficher clairement dans le header ou le menu si le profil actuel est Admin ou Auteur.

---

### UA 3.2.U3 — Autorisation avec les Gates Laravel

Objectif : utiliser les Gates pour autoriser ou interdire des actions concrètes selon le profil connecté.

* **Tutoriel 3.2.6 — Créer des Gates pour contrôler les actions sur les articles**
  Créer des Gates pour appliquer les règles métiers :

  * l’Auteur peut ajouter des articles et supprimer uniquement ses propres articles ;
  * l’Admin peut supprimer n’importe quel article mais ne peut pas en ajouter.
    Utiliser ces Gates dans les contrôleurs pour bloquer les actions non autorisées.

* **Tutoriel 3.2.7 — Utiliser les Gates dans les vues Blade avec `@can` / `@cannot`**
  Réutiliser les mêmes Gates dans les vues Blade pour afficher ou masquer les boutons “Ajouter” et “Supprimer” selon le profil connecté et le propriétaire de l’article.

---

### UA 3.2.U4 — Introduction aux Policies Laravel

Objectif : découvrir comment centraliser la logique d’autorisation autour d’un modèle avec une Policy.

* **Tutoriel 3.2.8 — Première Policy sur les articles et comparaison avec les Gates**
  Générer une Policy pour le modèle `Article`, y déplacer une règle existante (par exemple la suppression), l’utiliser dans un contrôleur et dans une vue, puis comparer ce fonctionnement avec la version basée uniquement sur les Gates.

## 🧩 Organisation concrète

### Ordre conseillé des tutoriels

1. **3.2.1 — Découvrir l’authentification et l’autorisation dans Laravel**

   * Clarification des concepts de base, appliqués au projet fil rouge.

2. **3.2.2 — Activer Laravel UI sur le projet fil rouge**

   * Mise en place de l’authentification (login/register/logout) sur le projet.

3. **3.2.3 — Protéger l’espace d’administration avec le middleware `auth`**

   * Distinction claire entre espace public et espace `/admin` protégé.

4. **3.2.4 — Gérer les profils Admin / Auteur avec `is_admin`**

   * Création des deux profils, ajout du champ `is_admin` et comptes de test.

5. **3.2.5 — Afficher le profil connecté dans l’interface**

   * Rendre visible dans l’interface quel type de profil est connecté (badge, texte…).

6. **3.2.6 — Créer des Gates pour contrôler les actions sur les articles**

   * Traduire les règles métiers (qui peut ajouter / supprimer quoi) en Gates.

7. **3.2.7 — Utiliser les Gates dans les vues Blade avec `@can` / `@cannot`**

   * Afficher ou non les boutons d’action selon le résultat des Gates.

8. **3.2.8 — Première Policy sur les articles et comparaison avec les Gates**

   * Créer une Policy pour `Article`, y déplacer une règle existante, et comparer ce fonctionnement avec celui basé sur les Gates.

### Mode de travail recommandé

* **Mode de travail :**

  * individuel pour les tutoriels 3.2.1 à 3.2.3 (mise en place de base),
  * en **binôme** pour les tutoriels 3.2.4 à 3.2.8 (profils, Gates, Policy), afin de discuter des règles “qui a le droit de faire quoi”.

* **Support :**

  * cette autoformation s’appuie sur :

    * les tutoriels N1 listés ci-dessus, à suivre strictement dans l’ordre 3.2.1 → 3.2.8,
    * le projet fil rouge Laravel dans l’état obtenu après les versions précédentes (interface publique + CRUD).

* **Durée estimée :**

  * environ **4 à 6 heures**, selon ton niveau initial et le temps passé à tester les différents scénarios de sécurité (Admin/Auteur, connecté/non connecté).

## 🎯 Livrables attendus (fin d’autoformation)

À la fin de cette autoformation, tu dois pouvoir montrer :

* un **projet fil rouge Laravel** où :

  * l’authentification Laravel UI fonctionne (inscription, connexion, déconnexion) ;
  * la route `/admin` est protégée par le middleware `auth` (redirection vers `/login` si non connecté) ;
  * deux profils existent : **Admin** et **Auteur**, avec un affichage clair du profil connecté dans l’interface ;

* un **comportement cohérent des droits sur les articles** :

  * l’Auteur peut ajouter des articles et ne supprimer que les siens ;
  * l’Admin peut supprimer n’importe quel article mais ne peut pas en ajouter ;
  * les boutons d’action (ajouter, supprimer) sont affichés ou cachés selon le profil et le propriétaire de l’article, grâce aux **Gates** et/ou à la **Policy** ;

* une **courte trace écrite** (quelques lignes dans un fichier `README.md`, un pad ou un commentaire) qui explique :

  * la différence entre **authentification** et **autorisation** dans ton projet,
  * comment tu as utilisé `is_admin`, les Gates et la Policy liée à `Article` pour mettre en place ces règles de sécurité.
