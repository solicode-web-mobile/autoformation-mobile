# 📘 3.2.4 — Gérer les profils Admin / Auteur avec `is_admin`

> Tutoriel 3.2.4 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Tu as maintenant :

* un système d’**authentification fonctionnel** avec Laravel UI (3.2.2),
* un espace `/admin` **protégé** par le middleware `auth` (3.2.3).

Problème :
pour l’instant, **tous les utilisateurs sont au même niveau**. Laravel sait qui est connecté, mais :

> il ne sait pas encore si cet utilisateur est **Admin** ou **Auteur**.

Dans ce tutoriel, tu vas introduire une distinction simple :

* **Admin** : utilisateur “spécial”, qui aura plus de droits dans l’admin ;
* **Auteur** : utilisateur “standard”, qui crée des articles.

Tu vas le faire avec un **champ booléen `is_admin`** sur la table `users`.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* créer une **migration** pour ajouter un champ `is_admin` à la table `users` ;
* configurer ce champ comme **booléen** dans le modèle `User` ;
* créer **deux comptes de test** : un Admin et un Auteur ;
* vérifier dans le code la valeur de `is_admin` pour l’utilisateur connecté.

---

## 3️⃣ Pré-requis

Tu dois déjà :

* avoir un projet Laravel du **projet fil rouge** qui tourne ;
* avoir activé **Laravel UI** et testé login/register (tutoriel 3.2.2) ;
* avoir protégé `/admin` avec le middleware `auth` (tutoriel 3.2.3) ;
* savoir lancer les commandes artisan de base :

  ```bash
  php artisan serve
  php artisan migrate
  ```

---

## 4️⃣ Rappel métier : pourquoi `is_admin` ?

Dans l’autoformation, on a décidé d’avoir **deux profils** simples :

* **Auteur** : peut ajouter des articles, et supprimer uniquement les siens ;
* **Admin** : peut supprimer n’importe quel article, mais ne peut pas en ajouter.

Pour que Laravel puisse appliquer ces règles, il doit pouvoir répondre à la question :

> “L’utilisateur connecté est-il un **Admin** ou un **Auteur** ?”

D’où l’idée d’un champ simple :

* `is_admin = 0` → Auteur ;
* `is_admin = 1` → Admin.

---

## 5️⃣ Étapes guidées (N1 — Imiter)

---

### 🧩 Étape 1 — Créer la migration pour ajouter `is_admin` à `users`

**Action**

1. Ouvre un terminal.

2. Place-toi dans le dossier de ton projet :

   ```bash
   cd chemin/vers/ton/projet-blog
   ```

3. Crée une migration pour ajouter le champ `is_admin` :

   ```bash
   php artisan make:migration add_is_admin_to_users_table --table=users
   ```

4. Laravel crée un fichier de migration dans `database/migrations`.
   Ouvre le fichier correspondant (il commence par la date et l’heure, puis `add_is_admin_to_users_table`).

#### ▶ Résultat attendu

* Un fichier de migration `add_is_admin_to_users_table` existe dans `database/migrations`.
* Ce fichier contient les méthodes `up()` et `down()` prêtes à être complétées.

#### 💡 Explication

La commande `make:migration` prépare un fichier pour **modifier** la table `users`.
Tu vas y ajouter le champ `is_admin`.

---

### 🧩 Étape 2 — Ajouter le champ booléen `is_admin` dans la migration

**Action**

Dans le fichier de migration ouvert, complète les méthodes `up()` et `down()` :

```php
public function up(): void
{
    Schema::table('users', function (Blueprint $table) {
        $table->boolean('is_admin')->default(false)->after('email');
    });
}

public function down(): void
{
    Schema::table('users', function (Blueprint $table) {
        $table->dropColumn('is_admin');
    });
}
```

> 💡 `->default(false)` signifie : **par défaut**, tous les nouveaux utilisateurs ne sont pas Admin.
> On se servira de ça pour considérer qu’un utilisateur classique est un **Auteur**.

#### ▶ Résultat attendu

* Le champ `is_admin` est bien défini comme **booléen**, avec une valeur par défaut `false`.

#### 💡 Explication

Tu demandes à Laravel :

* d’ajouter un **nouveau champ** à la table `users` ;
* ce champ est un **booléen** (vrai/faux) ;
* par défaut, tous les utilisateurs seront **Auteur** (`is_admin = false`).

C’est une solution **simple** pour distinguer deux rôles.

---

### 🧩 Étape 3 — Exécuter la migration

**Action**

Dans le terminal, exécute :

```bash
php artisan migrate
```

#### ▶ Résultat attendu

* La migration s’exécute **sans erreur**.
* Dans la base de données, la table `users` contient maintenant une colonne `is_admin`.

> Tu peux vérifier cela avec ton outil habituel (phpMyAdmin, Adminer, TablePlus, DBeaver…).

#### 💡 Explication

`php artisan migrate` applique ta migration et **modifie la structure de la table `users`**.
Tous les utilisateurs existants reçoivent une valeur par défaut (`is_admin = 0`).

---

### 🧩 Étape 4 — Mettre à jour le modèle `User` (cast booléen)

Tu vas maintenant préparer le modèle `User` pour que Laravel manipule `is_admin` comme **un booléen** (`true` / `false`) et pas seulement comme `0` / `1`.

**Action**

1. Ouvre le modèle `User` : `app/Models/User.php`.
2. Repère la propriété `$casts` (ou ajoute-la si elle n’existe pas).
3. Ajoute le cast suivant :

```php
class User extends Authenticatable
{
    use HasFactory, Notifiable;

    // ...

    protected $casts = [
        'email_verified_at' => 'datetime',
        'is_admin' => 'boolean',
    ];
}
```

> Si `$casts` existe déjà, **ajoute simplement** la ligne `'is_admin' => 'boolean',`.

#### ▶ Résultat attendu

* Le modèle `User` contient un cast `'is_admin' => 'boolean'`.

#### 💡 Explication

Le cast indique à Laravel :

> “Quand tu lis ou écris `is_admin`, considère que c’est un **booléen**.”

Dans ton code, tu pourras faire :

```php
if (Auth::user()->is_admin) {
    // comportement Admin
}
```

sans te soucier de savoir si c’est `0`/`1` ou `true`/`false`.

---

### 🧩 Étape 5 — Créer un compte Auteur et un compte Admin

Tu vas maintenant créer **deux comptes de test** :

* un **Auteur** (profil normal),
* un **Admin** (profil spécial).

#### a) Créer deux utilisateurs via l’interface

**Action**

1. Lance le serveur :

   ```bash
   php artisan serve
   ```

2. Va sur `/register` et crée :

   * un premier compte, par exemple :

     * Nom : `Auteur Test`
     * Email : `auteur@test.com`
     * Mot de passe : `password` (ou autre)

   * un deuxième compte, par exemple :

     * Nom : `Admin Test`
     * Email : `admin@test.com`
     * Mot de passe : `password` (ou autre)

3. Vérifie dans la base de données (table `users`) que **les deux lignes existent**.

#### b) Transformer un utilisateur en Admin

Tu vas maintenant mettre `is_admin = 1` pour le compte Admin.

**Option 1 — Via l’outil de gestion MySQL (phpMyAdmin, etc.)**

* Ouvre la table `users`.
* Repère la ligne avec l’email `admin@test.com`.
* Modifie la colonne `is_admin` à `1` (ou `true` selon l’interface).
* Laisse `is_admin = 0` pour `auteur@test.com`.

**Option 2 — Via Tinker (si tu es à l’aise)**

Dans le terminal :

```bash
php artisan tinker
```

Puis :

```php
$user = App\Models\User::where('email', 'admin@test.com')->first();
$user->is_admin = true;
$user->save();
```

Quitte Tinker ensuite (`exit`).

#### ▶ Résultat attendu

Dans la table `users` :

* `auteur@test.com` → `is_admin = 0` (Auteur) ;
* `admin@test.com` → `is_admin = 1` (Admin).

#### 💡 Explication

Tu viens de **concrétiser** tes deux profils dans la base :

* tu as un utilisateur “normal” (Auteur),
* et un utilisateur “spécial” (Admin).

Dans les tutoriels suivants, tu utiliseras ce champ pour :

* afficher des informations différentes,
* autoriser ou interdire certaines actions.

---

### 🧩 Étape 6 — Vérifier le comportement dans le code

Avant d’utiliser `is_admin` dans l’interface (ce sera 3.2.5), tu peux déjà vérifier que Laravel comprend bien ce champ.

**Action**

1. Dans ta vue `admin/dashboard.blade.php`, remplace (ou complète) le contenu de la section `content` par exemple :

   ```blade
   {{-- resources/views/admin/dashboard.blade.php --}}
   @extends('layouts.app')

   @section('content')
       <div class="max-w-5xl mx-auto px-4 py-8">
           <h1 class="text-2xl font-semibold mb-4">Espace d’administration</h1>

           @auth
               <p class="mb-2">Utilisateur connecté : {{ Auth::user()->name }}</p>

               @if (Auth::user()->is_admin)
                   <p class="text-sm text-emerald-700 font-medium">
                       Profil détecté : <span class="font-semibold">Admin</span>
                   </p>
               @else
                   <p class="text-sm text-sky-700 font-medium">
                       Profil détecté : <span class="font-semibold">Auteur</span>
                   </p>
               @endif
           @endauth
       </div>
   @endsection
   ```

2. Connecte-toi avec :

   * `auteur@test.com` → va sur `/admin` ;
   * `admin@test.com` → va sur `/admin`.

#### ▶ Résultat attendu

* Avec `auteur@test.com` → tu vois “Profil détecté : Auteur”.
* Avec `admin@test.com` → tu vois “Profil détecté : Admin”.

#### 💡 Explication

Tu as la preuve que :

* `Auth::user()` récupère bien l’utilisateur connecté ;
* le champ `is_admin` fonctionne et est bien interprété comme un **booléen**.

Ce test prépare directement le tutoriel **3.2.5**, où tu rendras ce profil visible dans le header/menu de l’interface.

## 6️⃣ Vérification & erreurs fréquentes

| Problème                                             | Cause probable                                       | Piste de solution                                                                                |
| ---------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Erreur lors de `php artisan migrate`                 | Migration mal écrite ou déjà exécutée                | Vérifie la syntaxe, regarde le message d’erreur exact, corrige la migration si besoin.           |
| La colonne `is_admin` n’apparaît pas dans `users`    | Migration non exécutée ou base de données différente | Vérifie `.env` (base utilisée), relance `php artisan migrate`.                                   |
| `Auth::user()->is_admin` renvoie toujours `null`     | Champ non présent ou erreur dans le cast             | Vérifie la table `users`, le nom exact de la colonne, et la propriété `$casts` du modèle `User`. |
| Impossible de distinguer Admin / Auteur dans l’admin | Les deux comptes ont la même valeur `is_admin`       | Vérifie la table `users`, modifie l’un des comptes (Admin) en `is_admin = 1`.                    |
| Tinker ne trouve pas l’utilisateur                   | Mauvais email ou namespace du modèle                 | Vérifie l’email exact, et utilise `App\Models\User` dans Tinker.                                 |
