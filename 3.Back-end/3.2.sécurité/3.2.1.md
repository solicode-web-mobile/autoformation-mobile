# 📘 3.2.1 — Découvrir l’authentification et l’autorisation dans Laravel

> Tutoriel 3.2.1 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans ce tutoriel, tu vas **clarifier les notions d’authentification et d’autorisation** à partir du blog Laravel du projet fil rouge.
Cet apprentissage te servira ensuite pour **choisir les bons outils Laravel** (middleware `auth`, Gates, Policies…) dans les tutoriels suivants.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* **distinguer authentification et autorisation** dans un projet Laravel concret ;
* **identifier les rôles principaux** (Visiteur, Auteur, Admin) de l’admin du blog ;
* **construire un tableau “qui a le droit de faire quoi ?”** qui servira de base aux règles de sécurité de la version V6.

---

## 3️⃣ Pré-requis

* Avoir déjà ouvert et lancé le **projet fil rouge Laravel** (versions précédentes).
* Savoir, au moins globalement, ce qu’est :

  * une **route** (`routes/web.php`),
  * un **contrôleur**,
  * une **vue Blade**.
* Avoir une idée du fonctionnement du **CRUD d’articles** (créer / lire / mettre à jour / supprimer).

Si ce n’est pas clair, prends quelques minutes pour revoir le CRUD réalisé dans les versions précédentes avant de continuer.

---

## 4️⃣ Explication théorique (courte)

Avant de coder, on clarifie les mots.

* **Authentification** (*authentication*)
  → Répond à la question : **“Qui es-tu ?”**
  Dans Laravel, c’est le fait de **se connecter** (login), **se déconnecter** (logout), et savoir **quel utilisateur est connecté** (`Auth::user()`).

* **Autorisation** (*authorization*)
  → Répond à la question : **“Qu’as-tu le droit de faire ?”**
  Exemples : “Peux-tu accéder à `/admin` ?” “Peux-tu supprimer cet article ?”

Dans le blog du projet fil rouge :

* l’**authentification** dira **quel utilisateur** est connecté ;
* l’**autorisation** dira **quelles actions** cet utilisateur est autorisé à faire, selon son **rôle** (Visiteur, Auteur, Admin).

Les tutoriels suivants (3.2.2 → 3.2.8) montreront **comment** Laravel gère ça techniquement (Laravel UI, middleware `auth`, Gates, Policy).
Ici, on prépare le terrain avec une **vision claire du métier** : *qui a le droit de faire quoi ?*

---

## 5️⃣ Étapes de réalisation

Pour chaque étape, on suit la structure **Action → Résultat attendu → Explication**.

---

### 🧩 Étape 1 — Lister les zones du blog à protéger

Cette étape te permet de repérer les parties “sensibles” du blog qui ne doivent pas être accessibles librement.

**Action**

1. Sur une feuille, dans un pad, ou dans un fichier Markdown, écris le titre :

   > *“Zones principales du blog”*

2. Liste les pages / zones que tu connais déjà dans le projet, par exemple :

   * page d’accueil publique (`/`) ;
   * liste des articles publics (`/articles`) ;
   * page d’un article (`/articles/{slug}`) ;
   * espace d’administration (`/admin`) ;
   * formulaire de création d’article dans l’admin ;
   * bouton / action de suppression d’un article.

3. Organise-les dans un petit tableau **Zone / URL / Type d’accès souhaité** :

   | Zone / Page                | URL (exemple)                 | Type d’accès souhaité              |
   | -------------------------- | ----------------------------- | ---------------------------------- |
   | Accueil du blog            | `/`                           | Public (tout le monde)             |
   | Liste des articles         | `/articles`                   | Public (tout le monde)             |
   | Page d’un article          | `/articles/{slug}`            | Public (tout le monde)             |
   | Dashboard d’administration | `/admin`                      | Réservé aux utilisateurs connectés |
   | Création d’article         | `/admin/articles/create`      | Réservé à certains rôles           |
   | Suppression d’article      | `/admin/articles/{id}/delete` | Réservé à certains rôles           |

   Tu peux adapter les URLs aux routes exactes de ton projet si besoin.

#### ▶ Résultat attendu

Tu as un tableau clair qui liste :

* les **zones publiques** (accessibles à tous) ;
* les **zones à protéger** (réservées aux utilisateurs connectés et/ou à certains rôles).

#### 💡 Explication

Avant de parler de middleware ou de Gates, il faut **comprendre le métier** : quelles parties de l’application sont “sensibles” ?
Ce tableau t’aide à voir **où la sécurité est nécessaire**. Les zones publiques resteront accessibles à tous, les autres seront protégées par l’authentification et l’autorisation.

---

### 🧩 Étape 2 — Identifier les rôles du blog (Visiteur, Auteur, Admin)

Cette étape te permet de définir clairement *qui* utilise ton application.

**Action**

1. Ajoute un nouveau titre dans ton document :

   > *“Rôles du blog”*

2. Liste au minimum **3 rôles** :

   * **Visiteur** : personne non connectée qui lit les articles.
   * **Auteur** : utilisateur connecté qui écrit des articles.
   * **Admin** : utilisateur connecté responsable de la gestion globale.

3. Complète le tableau suivant en l’adaptant si besoin :

   | Rôle     | Description courte                                                    |
   | -------- | --------------------------------------------------------------------- |
   | Visiteur | Personne non connectée qui peut lire les articles publics.            |
   | Auteur   | Utilisateur connecté qui peut écrire des articles.                    |
   | Admin    | Utilisateur connecté qui gère le blog (articles, utilisateurs, etc.). |

#### ▶ Résultat attendu

Tu as un tableau avec **les 3 rôles principaux** du blog, chacun avec une description simple.

#### 💡 Explication

Les **rôles** sont au cœur de l’autorisation : les règles “qui a le droit de faire quoi ?” dépendent d’eux.
Dans la version V6, ces rôles seront implémentés **simplement** avec un champ `is_admin` et un profil par défaut pour les auteurs. On construit d’abord la logique métier avant de passer à la technique.

---

### 🧩 Étape 3 — Construire le tableau “qui a le droit de faire quoi ?”

Cette étape te permet de transformer tes idées en **règles d’autorisation claires**.

**Action**

1. Ajoute un nouveau titre :

   > *“Qui a le droit de faire quoi ?”*

2. Reprends les **rôles** de l’étape 2 et les **actions importantes** du blog.
   Par exemple :

   * Lire les articles publics ;
   * Accéder au dashboard `/admin` ;
   * Créer un article ;
   * Modifier un article ;
   * Supprimer un article.

3. Crée un tableau **Rôle × Action**, et remplis-le avec ✔️ / ❌ selon la logique que tu souhaites pour la version V6.
   Exemple de base (à adapter selon les consignes de l’autoformation) :

   | Action / Rôle                    | Visiteur | Auteur | Admin |
   | -------------------------------- | :------: | :----: | :---: |
   | Lire les articles publics        |    ✔️    |   ✔️   |   ✔️  |
   | Accéder à `/admin`               |     ❌    |   ✔️   |   ✔️  |
   | Créer un article                 |     ❌    |   ✔️   |   ❌   |
   | Modifier ses propres articles    |     ❌    |   ✔️   |   ✔️  |
   | Supprimer ses propres articles   |     ❌    |   ✔️   |   ✔️  |
   | Supprimer n’importe quel article |     ❌    |    ❌   |   ✔️  |

4. Vérifie que le tableau respecte bien les règles décrites dans l’autoformation (par exemple : “L’Auteur peut ajouter des articles et supprimer uniquement les siens ; l’Admin peut supprimer n’importe quel article mais ne peut pas en ajouter.”). Ajuste si besoin.

#### ▶ Résultat attendu

Tu obtiens un tableau lisible qui résume **toutes les règles d’accès** importantes de ton blog :

* pour chaque action,
* tu sais **quel rôle** a le droit de la faire.

#### 💡 Explication

Ce tableau est le **cœur de l’autorisation** :

* il ne dépend pas encore de Laravel ;
* il exprime les **règles métier** de ton application ;
* il servira de base pour écrire les conditions avec les outils Laravel (middleware, Gates, Policy).

Si ce tableau est clair, la suite (implémentation technique) sera beaucoup plus simple.

---

### 🧩 Étape 4 — Relier tes règles aux notions Laravel

Cette étape te prépare aux tutoriels suivants en reliant tes idées métier aux outils Laravel.

**Action**

1. Sous ton tableau “Qui a le droit de faire quoi ?”, ajoute un bloc de texte :

   > *“Comment Laravel va gérer ça ?”*

2. Pour chaque grande idée, indique **quel outil Laravel** sera utilisé :

   * **Savoir qui est connecté** → *Authentification*
     → assurée par **Laravel UI** (tutoriel 3.2.2).

   * **Empêcher un utilisateur non connecté d’entrer dans `/admin`**
     → autorisation simple sur les routes
     → gérée par le **middleware `auth`** (tutoriel 3.2.3).

   * **Différencier Admin / Auteur dans le code**
     → profil stocké dans la base (`is_admin`), accessible via `Auth::user()`
     → mis en place dans les tutoriels 3.2.4 et 3.2.5.

   * **Autoriser ou interdire certaines actions (supprimer, créer…) selon le rôle**
     → autorisation fine
     → gérée par les **Gates** et les **Policies** (tutoriels 3.2.6 → 3.2.8).

3. Écris quelques phrases du type :

   * “La **connexion / déconnexion** sera gérée par l’authentification Laravel (Laravel UI).”
   * “Le fait de **bloquer l’accès à `/admin`** pour les non connectés sera géré par le **middleware `auth`**.”
   * “Le fait de **limiter la suppression d’un article** à certains rôles sera géré par des **Gates** ou une **Policy**.”

#### ▶ Résultat attendu

Tu as un petit paragraphe qui fait le lien entre :

* tes **règles métier** (tableau rôles / actions),
* et les **outils Laravel** que tu utiliseras plus tard.

#### 💡 Explication

L’idée n’est pas encore de coder, mais de savoir **où tu vas** :

* **Authentification** → qui est connecté ?
* **Autorisation** → quelles actions est-il autorisé à faire ?
* **Middleware / Gates / Policies** → outils Laravel pour traduire ces décisions métier en code.

En N1, tu imiteras ensuite des exemples concrets qui appliquent ces règles à ton projet.

## 6️⃣ Vérification et erreurs fréquentes

| Problème                                           | Cause probable                                      | Solution                                                                                                      |
| -------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Tu confonds encore authentification / autorisation | Définitions pas clarifiées, pas d’exemples concrets | Réécris en une phrase : “Authentification = … / Autorisation = …” avec ton propre exemple.                    |
| Ton tableau rôles / actions est flou               | Actions pas assez précises ou rôles mal définis     | Reprends les actions une par une : lire, créer, modifier, supprimer… et décide clairement pour chaque rôle.   |
| Tu ne sais pas quel outil Laravel utilisera quoi   | Tu mélanges middleware, Gates, Policies             | Revois l’étape 4 et garde une phrase simple par outil (“middleware = contrôle à l’entrée de la route”, etc.). |
| Tu veux déjà coder tout de suite                   | Tu as sauté la phase de réflexion métier            | Termine d’abord ton tableau et tes phrases de lien avec Laravel avant de passer au tutoriel 3.2.2.            |
