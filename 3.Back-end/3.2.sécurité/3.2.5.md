# 📘 3.2.5 — Afficher le profil connecté dans l’interface

> Tutoriel 3.2.5 issu de l’autoformation : 3.2. Sécurité et accès à l’admin (N1).

---

## 1️⃣ Introduction

Dans les tutoriels précédents, tu as :

* protégé l’admin avec le middleware **`auth`** (3.2.3),
* ajouté un champ **`is_admin`** pour distinguer Admin / Auteur (3.2.4).

Laravel sait donc **qui est connecté** et **s’il est Admin ou Auteur**.
Mais pour l’instant, **l’interface ne montre rien** : l’apprenant ne voit pas son profil.

Dans ce tutoriel, tu vas :

> afficher **dans le header ou le menu** le **nom de l’utilisateur connecté** et un **badge “Admin” ou “Auteur”**.

---

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

* utiliser `Auth::user()` dans une vue Blade ;
* utiliser `@auth` et `@guest` pour afficher du contenu selon l’état de connexion ;
* afficher un **badge de rôle** (Admin / Auteur) dans la barre de navigation ou l’interface ;
* tester l’affichage avec **deux comptes** : un Auteur et un Admin.

---

## 3️⃣ Pré-requis

Tu dois avoir :

* un projet Laravel du **projet fil rouge** fonctionnel ;
* l’authentification **Laravel UI** activée (tutoriel 3.2.2) ;
* l’espace `/admin` protégé par `auth` (tutoriel 3.2.3) ;
* le champ **`is_admin`** ajouté à la table `users` et casté en booléen (3.2.4) ;
* **deux comptes** dans la base :

  * un **Auteur** (`is_admin = 0`),
  * un **Admin** (`is_admin = 1`).

Si ce n’est pas le cas, termine d’abord le tutoriel 3.2.4.

---

## 4️⃣ Où afficher le profil ?

Dans la plupart des projets Laravel avec Laravel UI, tu as un **layout global** :

* `resources/views/layouts/app.blade.php`

Ce layout contient souvent :

* la **barre de navigation** (navbar),
* les liens **Login / Register** quand tu n’es pas connecté,
* les liens **Logout / Dashboard** quand tu es connecté.

C’est **l’endroit idéal** pour afficher :

* le **nom de l’utilisateur connecté** ;
* son **rôle** (Admin / Auteur) sous forme de **badge**.

---

## 5️⃣ Étapes guidées (N1 — Imiter)

---

### 🧩 Étape 1 — Repérer le layout principal

**Action**

1. Ouvre ton projet dans ton éditeur de code.

2. Navigue dans `resources/views/layouts/`.

3. Ouvre le fichier :

   ```text
   resources/views/layouts/app.blade.php
   ```

4. Cherche à l’intérieur la partie qui correspond à la **barre de navigation**.
   Par exemple, quelque chose comme :

   ```blade
   <nav class="navbar navbar-expand-md navbar-light bg-white shadow-sm">
       <div class="container">
           <a class="navbar-brand" href="{{ url('/') }}">
               {{ config('app.name', 'Laravel') }}
           </a>

           <!-- ... -->
       </div>
   </nav>
   ```

5. Plus bas dans la navbar, tu devrais voir un bloc avec `@guest` / `@else` / `@endguest`.

#### ▶ Résultat attendu

* Tu as trouvé le layout global `app.blade.php`.
* Tu as repéré où sont affichés les liens d’authentification (Login, Register, Logout…).

#### 💡 Explication

Le layout `app.blade.php` est utilisé par beaucoup de pages (via `@extends('layouts.app')`).
En modifiant **une seule fois** ce fichier, tu peux afficher le profil sur toutes les pages qui l’utilisent.

---

### 🧩 Étape 2 — Utiliser `@auth` et `Auth::user()` dans la navbar

Tu vas maintenant **afficher le nom et le rôle** de l’utilisateur dans la barre de navigation, uniquement lorsqu’il est connecté.

**Action**

1. Dans `app.blade.php`, repère le bloc ressemblant à ceci :

   ```blade
   @guest
       {{-- Liens pour les invités (non connectés) --}}
   @else
       {{-- Liens pour les utilisateurs connectés --}}
   @endguest
   ```

   Selon ta version, ce bloc peut être légèrement différent, mais l’idée est la même.

2. Dans la partie **utilisateur connecté** (le bloc `@else`), ajoute un petit morceau de code pour afficher :

   * le **nom** de l’utilisateur,
   * un **badge** Admin / Auteur.

   Par exemple :

   ```blade
   @else
       <li class="nav-item">
           <span class="nav-link">
               Bonjour, {{ Auth::user()->name }}
               @if (Auth::user()->is_admin)
                   <span class="badge bg-danger ms-2">Admin</span>
               @else
                   <span class="badge bg-secondary ms-2">Auteur</span>
               @endif
           </span>
       </li>

       <li class="nav-item dropdown">
           {{-- menu existant avec Logout, etc. --}}
       </li>
   @endguest
   ```

> Si ta navbar n’est pas structurée exactement comme ça, adapte en suivant la même idée :
> **dans la partie “utilisateur connecté” → afficher nom + badge**.

#### ▶ Résultat attendu

* Le code `Auth::user()->name` est utilisé dans la navbar.
* Un badge `Admin` ou `Auteur` est affiché selon la valeur de `is_admin`.

#### 💡 Explication

* `@guest` : partie affichée aux **visiteurs non connectés**.
* `@else` ou `@auth` : partie affichée aux **utilisateurs connectés**.
* `Auth::user()` : objet représentant l’utilisateur connecté.
* `Auth::user()->is_admin` : **booléen** (true/false) grâce au cast défini dans le modèle `User`.

---

### 🧩 Étape 3 — Tester avec un compte Auteur et un compte Admin

Tu vas maintenant vérifier que l’affichage change bien selon le profil.

**Action**

1. Assure-toi que ton serveur tourne :

   ```bash
   php artisan serve
   ```

2. **Test 1 — Auteur**

   * Va sur `/login`.
   * Connecte-toi avec le compte **Auteur** (`is_admin = 0`).
   * Regarde la navbar.

3. **Test 2 — Admin**

   * Clique sur le bouton de déconnexion (Logout).
   * Va à nouveau sur `/login`.
   * Connecte-toi avec le compte **Admin** (`is_admin = 1`).
   * Regarde la navbar.

#### ▶ Résultat attendu

* Avec le compte Auteur, tu vois quelque chose comme :

  > Bonjour, Auteur Test [Badge “Auteur”]

* Avec le compte Admin, tu vois :

  > Bonjour, Admin Test [Badge “Admin”]

#### 💡 Explication

Tu viens de **rendre visible** le profil connecté :

* l’utilisateur voit **qui il est** (nom),
* et **quel rôle** il a (Admin / Auteur).

C’est important pour que le comportement de l’interface (boutons affichés, droits d’action…) soit cohérent aux yeux de l’utilisateur.

---

### 🧩 Étape 4 — (Optionnel) Ajouter un lien vers l’admin pour certains profils

> Étape optionnelle, mais utile pour l’ergonomie.

Tu peux décider que **seuls certains rôles** voient un lien direct vers `/admin` dans la navbar.

Exemple : **Admin et Auteur** voient tous les deux le lien d’admin (car ils utilisent tous les deux le back-office).

**Action**

Dans le bloc `@auth` / `@else` (utilisateur connecté), ajoute par exemple :

```blade
@auth
    <li class="nav-item">
        <a class="nav-link" href="{{ route('admin.dashboard') }}">
            Admin
        </a>
    </li>

    <li class="nav-item">
        <span class="nav-link">
            Bonjour, {{ Auth::user()->name }}
            @if (Auth::user()->is_admin)
                <span class="badge bg-danger ms-2">Admin</span>
            @else
                <span class="badge bg-secondary ms-2">Auteur</span>
            @endif
        </span>
    </li>
@endauth
```

> Si tu veux un comportement différent (par exemple : seul Admin voit le lien), tu peux envelopper le lien dans un `@if(Auth::user()->is_admin)`.

#### ▶ Résultat attendu

* Quand tu es connecté (Auteur ou Admin), tu vois un lien vers l’admin.
* Tu vois toujours le nom et le badge.

#### 💡 Explication

Tu commences à **adapter l’interface** au rôle.
C’est une première étape avant de cacher/afficher certains **boutons d’action** avec des Gates (tutoriels 3.2.6 et 3.2.7).

## 6️⃣ Vérification & erreurs fréquentes

| Problème                                                     | Cause probable                                         | Piste de solution                                                                       |
| ------------------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| Erreur “Attempt to read property 'name' on null”             | `Auth::user()` est `null` (pas d’utilisateur connecté) | Encadre ton code avec `@auth` / `@endauth` ou vérifie que tu es connecté.               |
| Badge Admin/Auteur ne change jamais                          | `is_admin` mal rempli ou pas casté en booléen          | Vérifie la table `users` et la propriété `$casts` du modèle `User`.                     |
| Rien ne s’affiche dans la navbar pour l’utilisateur connecté | Code ajouté dans la mauvaise section de la navbar      | Vérifie que ton code est dans le bloc `@auth` ou `@else` (partie utilisateur connecté). |
| La navbar ne s’affiche pas du tout                           | Erreur de syntaxe Blade (`@if`, `@endif`, parenthèses) | Vérifie les `@if`, `@endif`, parenthèses et accolades dans le fichier `app.blade.php`.  |
| Tu ne sais pas quel layout est utilisé                       | Certaines vues n’`@extends` pas `layouts.app`          | Vérifie en haut des vues si elles contiennent `@extends('layouts.app')`.                |

---

## 7️⃣ Lien avec le projet fil rouge

Grâce à ce tutoriel, ton blog Laravel :

* affiche **le profil connecté** (nom + rôle) de manière claire ;
* montre à l’utilisateur **de quel type de compte** il dispose (Admin / Auteur).

C’est important pour :

* comprendre pourquoi certains boutons sont visibles ou non,
* préparer l’utilisation des **Gates** et de la **Policy** sur les articles :

  * l’Auteur pourra ajouter des articles et supprimer seulement les siens ;
  * l’Admin pourra supprimer n’importe quel article, mais pas en ajouter.

L’affichage du rôle rend ces règles **comprises** par l’utilisateur, pas seulement par le code.
