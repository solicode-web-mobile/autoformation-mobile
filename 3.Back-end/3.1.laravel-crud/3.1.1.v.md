# 📘 3.1.1 — Installation et configuration d’un projet Laravel

## 1️⃣ Introduction

Dans ce tutoriel, tu vas **créer un nouveau projet Laravel** nommé par exemple `blog-solicode`, puis le **configurer correctement** : fichier `.env`, **clé d’application**, **connexion à la base**, **locale** et **timezone**.  
Cet apprentissage te servira ensuite pour développer le **CRUD Article** et, plus tard, l’**API** consommée par l’application mobile.

## 2️⃣ Objectif pédagogique

À la fin de ce tutoriel, tu seras capable de :

- **Installer un projet Laravel fonctionnel** avec Composer ;
- **Configurer le fichier `.env`** (APP\_NAME, base de données, APP\_URL) ;
- **Générer la clé d’application Laravel** et vérifier que tout fonctionne ;
- **Adapter la langue (locale) et le fuseau horaire (timezone)** à ton contexte.

## 3️⃣ Pré-requis

- Avoir **PHP ≥ 8.2** installé sur ta machine ;
- Avoir **Composer** installé (commande `composer` disponible dans le terminal) ;
- Avoir **MySQL 8+** installé et un utilisateur avec un mot de passe ;
- Savoir ouvrir un **terminal** / **invite de commandes** ;
- (Recommandé) : savoir exécuter quelques commandes **Git** (`git init`, `git status`, `git commit`).

## 4️⃣ Explication théorique (courte)

Avant de passer à la pratique, quelques notions importantes :

- **Laravel** est un **framework PHP** qui fournit une structure complète pour ton application (routes, contrôleurs, vues, modèles, etc.).
- Le fichier **`.env`** contient les **paramètres sensibles et spécifiques à ton environnement** : nom de l’application, base de données, mode debug, etc.
- La **clé d’application** (`APP_KEY`) est utilisée par Laravel pour chiffrer certaines données (sessions, tokens…). Sans elle, l’application lève des erreurs.
- La **locale** détermine la **langue** par défaut (messages, traductions) ; la **timezone** détermine le **fuseau horaire** utilisé pour les dates.
- Avoir un **projet propre et bien configuré** dès le départ évite beaucoup d’erreurs au moment d’ajouter des fonctionnalités (CRUD, API…).

> 💡 Garde en tête que ce projet `blog-solicode` sera ton **socle** pour la suite (CRUD Article, API, mobile). Soigne cette étape.

## 5️⃣ Étapes guidées (N1 — Imiter, pas à pas)

### 🧩 Étape 1 — Créer le dossier de travail et installer Laravel

- **Action** :  
  1. Ouvre ton **terminal** (ou PowerShell / Git Bash selon ton OS).  
  2. Place-toi dans le dossier où tu ranges tes projets (ex. `Documents/projets/`).  
  3. Lance la commande suivante pour créer un nouveau projet Laravel :

     ```bash
     composer create-project laravel/laravel blog-solicode
     ```

  4. Quand l’installation est terminée, entre dans le dossier :

     ```bash
     cd blog-solicode
     ```

- **Résultat attendu** :  
  Un nouveau dossier `blog-solicode` est créé. En te plaçant dedans et en listant son contenu, tu vois des dossiers comme `app/`, `routes/`, `resources/`, `config/`, etc.

- **Explication** :  
  La commande `composer create-project` télécharge la **dernière version de Laravel** et installe toutes les dépendances nécessaires. Le dossier `blog-solicode` contient maintenant la **structure de base** de ton application. Te placer dans ce dossier te permet d’exécuter les commandes `php artisan` sur ce projet.

🧠 Astuce : Si la commande `composer` n’est pas connue, vérifie que **Composer est bien installé** et ajouté à ton PATH.

---

### 🧩 Étape 2 — Préparer la configuration avec le fichier `.env`

- **Action** :  
  1. Duplique le fichier d’exemple `.env.example` en `.env` :

     ```bash
     cp .env.example .env
     ```

     (Sous Windows PowerShell, tu peux utiliser : `copy .env.example .env`)

  2. Ouvre le fichier `.env` dans ton éditeur (VS Code, par exemple).  
  3. Modifie au minimum les lignes suivantes pour les adapter à ton contexte :

     ```env
     APP_NAME="Blog Solicode"
     APP_ENV=local
     APP_DEBUG=true
     APP_URL=http://localhost:8000

     DB_CONNECTION=mysql
     DB_HOST=127.0.0.1
     DB_PORT=3306
     DB_DATABASE=blog_solicode
     DB_USERNAME=ton_utilisateur_mysql
     DB_PASSWORD=ton_mot_de_passe_mysql
     ```

     (Remplace `ton_utilisateur_mysql` et `ton_mot_de_passe_mysql` par tes valeurs réelles.)

- **Résultat attendu** :  
  Le fichier `.env` contient maintenant un **nom d’application** clair, une **URL locale** correcte et une **connexion MySQL** pointant vers une base `blog_solicode` que tu pourras créer.

- **Explication** :  
  Le fichier `.env` permet de **séparer la configuration du code**. Tu peux changer la base de données, l’URL ou le mode debug **sans modifier le code PHP**. En configurant correctement `APP_URL` et les variables `DB_*`, tu prépares ton projet pour exécuter des migrations et accéder à la base de données.

🧠 Astuce : Pense à **créer la base de données `blog_solicode`** dans MySQL (via phpMyAdmin ou une commande SQL `CREATE DATABASE blog_solicode;`) avant de lancer des migrations.

---

### 🧩 Étape 3 — Générer la clé d’application Laravel

- **Action** :  
  1. Dans le terminal, à la racine du projet (`blog-solicode`), exécute :

     ```bash
     php artisan key:generate
     ```

- **Résultat attendu** :  
  - La commande affiche un message du type : `Application key set successfully.`  
  - Dans le fichier `.env`, la variable `APP_KEY` est remplie avec une longue chaîne de caractères (par ex. `base64:...`).

- **Explication** :  
  Laravel utilise `APP_KEY` pour **chiffrer** certaines données sensibles (sessions, tokens…). Sans cette clé, tu risques des erreurs ou un comportement non sécurisé. La commande `php artisan key:generate` crée une clé aléatoire et l’inscrit dans ton `.env`.

⚠️ Attention : **Ne partage jamais** ton fichier `.env` complet (ni ta clé) sur un dépôt public (GitHub, etc.).

---

### 🧩 Étape 4 — Configurer la locale (langue) et la timezone (fuseau horaire)

- **Action** :  
  1. Ouvre le fichier `config/app.php` dans ton éditeur.  
  2. Repère les lignes suivantes et adapte-les :

     ```php
     'locale' => 'fr',
     'fallback_locale' => 'fr',
     'timezone' => 'Africa/Casablanca',
     ```

  3. Sauvegarde le fichier.

- **Résultat attendu** :  
  - La **langue par défaut** de Laravel est le français (`fr`).  
  - Le **fuseau horaire** utilisé pour les dates est `Africa/Casablanca`, adapté à ton contexte local.

- **Explication** :  
  Ces paramètres définissent la **langue des messages** (traductions, dates, etc.) et la **zone horaire** utilisée par `Carbon` et les fonctions de date de Laravel. En les configurant maintenant, tu évites les surprises (dates décalées, messages en anglais) dans ton futur CRUD et dans ton API.

🧠 Astuce : Tu peux plus tard ajouter des **fichiers de traduction** en français dans `lang/fr/` pour personnaliser les messages.

---

### 🧩 Étape 5 — Lancer le serveur de développement et vérifier l’installation

- **Action** :  
  1. Dans le terminal, toujours à la racine du projet, lance :

     ```bash
     php artisan serve
     ```

  2. Ouvre ton navigateur et va sur l’URL indiquée (souvent `http://127.0.0.1:8000` ou `http://localhost:8000`).  
  3. Vérifie que la **page d’accueil Laravel** s’affiche.

- **Résultat attendu** :  
  - Le terminal affiche que Laravel écoute sur `http://127.0.0.1:8000`.  
  - Dans le navigateur, tu vois la page de bienvenue Laravel (logo, texte “Laravel” ou page d’accueil par défaut).

- **Explication** :  
  La commande `php artisan serve` lance un **petit serveur de développement** intégré à Laravel. Il te permet de tester ton application en local sans configurer un serveur web complet. Voir la page d’accueil signifie que **ton installation est correcte** et que tu peux commencer à ajouter des routes, contrôleurs, vues, etc.

🧪 À toi de tester : Arrête le serveur avec `Ctrl + C` dans le terminal, puis relance-le pour t’habituer au cycle de développement.

---

### 🧩 Étape 6 — Initialiser un dépôt Git (optionnel mais recommandé)

- **Action** :  
  1. Toujours à la racine du projet, exécute :

     ```bash
     git init
     git add .
     git commit -m "Initialisation projet Laravel blog-solicode"
     ```

- **Résultat attendu** :  
  - Un dépôt Git est créé dans ton dossier.  
  - Un premier commit contient l’**état initial** de ton projet Laravel.

- **Explication** :  
  Versionner ton projet avec Git dès le début te permet de **suivre tes modifications**, de **revenir en arrière** et de **travailler en équipe** plus facilement. Ce dépôt sera utile quand tu ajouteras le CRUD, l’API et d’autres fonctionnalités.

⚠️ Attention : Pense à ajouter un fichier `.gitignore` (Laravel en fournit déjà un) pour **ne pas versionner** le dossier `vendor/` ni le fichier `.env`.

## 6️⃣ Vérification et erreurs fréquentes

| Problème                                    | Cause probable                                      | Solution                                                   |
| ------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------- |
| `composer` n’est pas reconnu                | Composer n’est pas installé ou pas dans le PATH    | Installer Composer ou ajouter son chemin au PATH          |
| Erreur de connexion MySQL                   | Mauvaise valeur dans `DB_USERNAME` / `DB_PASSWORD` | Vérifier l’utilisateur, le mot de passe et le nom de base |
| Message “No application encryption key”     | Clé d’application non générée                      | Lancer `php artisan key:generate`                         |
| Page Laravel ne s’affiche pas               | Serveur non lancé ou mauvaise URL                  | Lancer `php artisan serve` et ouvrir l’URL indiquée       |
| Dates/heures décalées                       | Mauvaise `timezone` dans `config/app.php`          | Mettre `'timezone' => 'Africa/Casablanca'` et sauvegarder |

## 7️⃣ Lien avec le fil rouge

Ce projet `blog-solicode` sera la **base technique** de ton **blog Laravel** :

- Côté **admin**, tu ajouteras bientôt un **CRUD Article** (création, édition, suppression, liste paginée).  
- Côté **public**, tu afficheras une **liste d’articles** et des **pages de détail**.  
- Plus tard, tu exposeras une **API REST** consommée par l’application mobile.

En ayant un projet Laravel **proprement installé et configuré**, tu évites des bugs difficiles à comprendre au moment d’ajouter ces fonctionnalités.
